# 刮刮乐小店（/tools/scratch-cards）

单人玩法：在商店买票 → 摆在桌子上（可拖）→ 点开像真票一样刮开涂层 → 中奖的拖进兑奖机换钱，
没中的拖进碎纸机变成纸屑；钱与纸屑两种货币用来升级刮刀、自动刮机器、兑奖机与碎纸机。

权限 slug：`scratch-cards`。页面 `/tools/scratch-cards`、接口 `/api/scratch/*`、
素材 `/image/scratch/*` 都要求该权限；别的工具不共享这张桌子的数据（单人、按账户隔离）。

## 货币

| 货币 | 存放位置 | 说明 |
| --- | --- | --- |
| 金钱 | `HoldemBalance.chips` | **与德州扑克是同一份余额**（需求确认的「互通」）；本工具不另存余额，钱一动两边同时变 |
| 纸屑 | `ScratchProfile.scraps` | 碎纸机产出，基础规则是「1 张票 = 1 单位纸屑」，与票价无关；升级后按等级加成 |

德州的「余额低于最小买入可自助补充」规则**没有改动**：刮刮乐是纯娱乐彩头，
长期回收率靠奖池概率（见下表）而不是靠玩家没钱来制造压力。

## 票种与玩法

票种、价格、奖池权重、格子布局全部在 `resources/content/scratch/tickets.json`；
服务端（`code/server/scratch-rules.js`）与客户端（`code/lib/scratch/catalog.ts`）读同一份文件，改数值不用改代码。

| 票种 key | 名称 | 票价 | 中奖方式 | 中奖率 | 平均奖金 | 长期回收率 |
| --- | --- | --- | --- | --- | --- | --- |
| `three-match` | 三连金 | 10 | 刮出三个相同金额即中该金额 | 38% | 15.9 | ≈60% |
| `lucky-symbol` | 好运符号 | 20 | 票面公布中奖符号，刮出三个即中奖 | 32% | 36.6 | ≈59% |
| `high-low` | 比大小 | 30 | 3 组「你 vs 庄家」，赢 2 组中 30、赢 3 组中 150 | 42% | 56.4 | ≈79% |
| `find-word` | 找中奖 | 5 | 9 格中给出 1~2 个「中奖」，出 1 个中 4、2 个中 15 | 50% | 5.7 | ≈57% |

> 表里的「平均奖金」与「长期回收率」由服务端按权重实时算出（`expectedReturn`），
> 商店卡片上也会显示，调数值时看它比看直觉可靠。

### 规则细节（防歧义设计）

- **三连金**：不中奖时每个金额最多出现两次，避免票面上「另一组也能三连」让人误判；
- **好运符号**：中奖符号以外的符号也最多两个；票面公布的中奖符号里**不含输赢信息**，刮开前就能看到；
- **比大小**：生成时直接避开平局，所以「赢了几组」永远不含糊；
- **找中奖**：整张票只在「中奖 / 谢谢参与」两种字之间分配，命中个数决定奖金档位。

## 界面与手感

- 页面是一屏布局，永不出现页面级滚动条：顶部货币条 + 左侧竖排商店 + 右侧桌面（右上兑奖机、右下碎纸机）：
  - 手机竖屏（≤760px）时侧边栏收窄到 148px、机器缩小、机器说明与票面规则文字收起，仍是一屏；
- **商店在左侧竖向排列**；四种票**一律是矩形**，靠长宽比与配色区分（不给票加锯齿、斜切、圆孔之类的外部轮廓）：
  - 三连金 = 宽横票（2.05 : 1）+ 金色；好运符号 = 竖票（0.72 : 1）+ 绿色；
  - 比大小 = 方票（1 : 1）+ 蓝色；找中奖 = 横票（1.45 : 1）+ 橙色；
  - 列表可滚动（只在侧边栏内部），所以以后加票种不会挤出屏幕。
- **桌面上的票可以随手拖动**：按住拖到任意位置，松手时把 `posX/posY/z` 写回数据库；
  - 拿起来的票自动抬到最上层（`z` 递增），重叠摆放时顺序也持久化；
  - 手指拖动不会被系统手势抢走（`touch-action: none`），页面本身不滚动；
  - 位置被夹在桌面内（3%~97%），不会拖出桌布找不到；
  - 把票拖到兑奖机/碎纸机上时机器会高亮，阶段 4 会在这里结算（现在只提示并把位置记下）。
- **点一下票（没有拖动）就聚焦刮奖**：票被放大成一张真票，其余界面退到模糊背景后面；
  已刮开的票再点开就是看结果，Esc 或点背景放回桌面。

## 刮开与揭晓（阶段 3）

- 聚焦视图是一张放大的矩形票（长宽比与桌上那张一致）：票头（票名 / 票价）→ 玩法说明（含票面公布的信息）
  → 游戏区（印刷格子 + 涂层）→ 票脚（刮开进度或结算）→ 动作按钮。
- **印刷层一直就在涂层下面**（这是手感的关键）：
  - 格子里的金额 / 符号 / 数字在买票时就随票下发（`ticket.print`），涂层只是盖在上面的一层 canvas；
  - 所以刮到哪就露出哪、**刮到的那一格会亮起来**（中奖格还会加一圈金光），而不是刮完才一起翻出来；
  - 服务端只保留「结算」：刮开进度达标后才确认中没中、多少钱（`ticket.outcome`），并据此决定能不能兑奖。
  - 「好运符号」的**中奖符号**属于印在票面上的公开信息，同样在 `print.legend` 里，刮开前就能看到。
- 刮开层是 `code/components/scratch/ScratchCanvas.tsx`：
  - 涂层由 canvas 画（渐变 + 斜纹 + 「用手指刮开涂层」提示），擦除用 `globalCompositeOperation = 'destination-out'`，
    笔刷是圆头线段，所以快速划也不会断成一串圆点；
  - 进度与**逐格进度**在同一个抽样循环里算出来（160ms 节流），逐格进度用来点亮已露出的格子；
  - 手机地址栏伸缩 / 旋屏导致尺寸变化时，把整张旧位图缩放贴回，已经刮掉的部分不会白刮；
  - 笔刷宽度来自 `scratch.brush`（占游戏区宽度的百分比），**阶段 5 的「刮刀升级」就是把它调大**。
- 结算流程：客户端刮到达标 → `POST /api/scratch/tickets/:id/reveal` → 服务端把状态改成 `scratched` 并首次下发 `outcome`
  → 涂层淡出、票脚出结果横幅、动作按钮出现。
- 安全边界（写清楚，免得以后把它误当成防作弊）：
  - 格子内容本来就在票上（真票也如此），客户端看得到不等于能改结果：中奖金额在买票时由服务端按种子定死；
  - `seed` 永不下发；钱的进出（买票、兑奖）全部由服务端确认并在同一个事务里落库；
  - 阈值只是手感门槛，服务端不校验手指是否真的划过（单人娱乐，跳过刮的动作没有收益）；
  - 重复 `reveal` 幂等：不重复计数，也不重复发奖；**结算不发钱**，钱要到兑奖机（阶段 4）才进账户。

## 票面外观（数据驱动，`shape` + `theme`）

票的形状、尺寸、配色全部写在 `resources/content/scratch/tickets.json`，客户端 `code/components/scratch/TicketArt.tsx` 只按配置画 SVG，**加一种长得不一样的票不需要写新组件**：

| 字段 | 作用 |
| --- | --- |
| `shape.aspect` | **票的长宽比**（宽 ÷ 高）：>1 横票、=1 方票、<1 竖票。票永远是矩形，形状差异只来自这里 |
| `shape.tableWidth` | 摆在桌面上时的宽度（桌面宽度的百分比） |
| `theme.accent` | 主题色（票名条、图案、卡片标题） |
| `theme.paper` / `theme.ink` | 纸面底色 / 印刷墨色 |
| `theme.foil` / `theme.edge` | 涂层金属色 / 描边色 |

`shape.kind` 只是给 CSS 和日志用的标签（`wide` / `tall` / `square` / `rounded`），不影响绘制。

票面上的图案也按玩法区分：三连金画三枚金币、好运符号画符号行（多于 3 个自动折两行）、比大小画两张号牌加 VS、找中奖画 3×3 圆点阵。
票名、票价与「涂层未刮开」目前都是票面的一部分；阶段 3 会把涂层换成真正可刮的 canvas。

## 兑奖机与碎纸机（阶段 4）

桌子右上角是**兑奖机**，右下角是**碎纸机**；把票拖过去松手就算递交（机器会高亮）。聚焦视图里也有同样的按钮，
手机上不用拖来拖去。

| 机器 | 接受什么票 | 结果 |
| --- | --- | --- |
| 兑奖机 | 已刮开且中奖的票 | 奖金进「金钱」（与德州扑克同一份余额），状态 → `redeemed`，钱与票在同一个事务里落库 |
| 兑奖机 | 没刮开 / 没中奖的票 | 拒绝并说明原因（提示改用碎纸机），不会消耗票 |
| 碎纸机 | 任何未结算的票（已刮开或未刮开） | 产出纸屑（`shredScraps` 基础 1 + 「碎纸机」升级加成），状态 → `shredded` |
| 碎纸机 | 未刮开的票 | **先弹二次确认**（"碎掉就再也没机会中奖了"），可一键改为"先刮一下" |

- 结算成功后票离开桌面（`sealed` / `scratched` 才算桌面上的票），槽位随之释放，可以继续买新票。
- 碎纸会撒一把纸屑粒子（纯 CSS 动画，1.4 秒后自动清理，不留在 DOM 里）。
- 两个动作都是**幂等**的：重复调用返回 `alreadySettled: true`，不会重复给钱或多给纸屑；
  已经碎掉的票不能再兑奖，已经兑过奖的票不能再碎（都是 409）。
- 统计会累计：`redeemed`（兑奖次数）、`prizeTotal`（奖金总额）、`shredded`（碎纸张数）、`scrapsTotal`（纸屑总量）；
  流水里钱和纸屑分开记（`currency: money | scraps`）。

## 服务端设计

- 结果**在买票那一刻**就按种子生成并存进 `ScratchTicket.resultJson`：
  随机数 = `crypto` 摘要 + xorshift128，同一个 seed 永远生成同一张票（可复现、可审计）。
- `seed` 与未刮开的 `resultJson` **绝不下发**给客户端（`status = sealed` 时 DTO 里 `result` 恒为 `null`），
  所以改前端刷不出奖；刮开、兑奖、碎纸都将是服务端动作。
- 钱、票、流水在**同一个 `prisma.$transaction`** 里完成：扣钱走 `holdem-store.applyChipsWithinTx`
  （筹码账户唯一写入路径），所以不会出现「钱扣了票没生成」。
- `ScratchLedger` 额外记一份刮刮乐自己的流水（含钱的镜像），用于在界面里看本工具的收支历史。

### 数据表（Prisma / SQLite）

| 表 | 作用 |
| --- | --- |
| `ScratchProfile` | 一人一行：`scraps`（纸屑）、`levelsJson`（升级等级）、`unlockedJson`（显式解锁的票种）、`statsJson` |
| `ScratchTicket` | 一行 = 桌面上的一张票：`kind / price / seed / resultJson / status / scratchRatio / posX / posY / z` |
| `ScratchLedger` | 流水：`currency`（money / scraps）、`delta`、`balance`、`kind`、`ticketId`、`note` |

`ScratchTicket.status` 取值：`sealed`（未刮开）→ `scratched`（已刮开）→ `redeemed`（已兑奖）/ `shredded`（已碎）。

### 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/scratch/profile` | 余额（= 筹码）、纸屑、升级等级、解锁、统计、桌面槽位 |
| GET | `/api/scratch/catalog` | 票种配置 + 期望回收率 + 是否解锁 + 配置问题 |
| GET | `/api/scratch/ledger` | 本工具流水（最近 50 条） |
| GET | `/api/scratch/tickets` | 桌上的票（未结算的；未刮开的票不含答案） |
| POST | `/api/scratch/tickets` | 买票 `{ kind }`：事务扣钱 + 生成票面 + 落库，返回票与新余额 |
| PATCH | `/api/scratch/tickets/:id` | 保存桌面坐标 `{ posX, posY, z }`（拖动松手时写入） |
| POST | `/api/scratch/tickets/:id/reveal` | 刮开结算 `{ scratchRatio }`：进度达标才确认结算；未达标 409，重复调用幂等 |
| POST | `/api/scratch/tickets/:id/redeem` | 兑奖：只接受「已刮开且中奖」的票，奖金进与德州扑克共用的余额 |
| POST | `/api/scratch/tickets/:id/shred` | 碎纸：产出纸屑（1 张 = 1 + 升级加成），未刮开的也能碎 |

写操作都要求同源请求；账户没有 `scratch-cards` 权限时统一 403。

## 部署与验证

新增了迁移，部署到已有环境时执行：

```powershell
npm run db:migrate        # 应用 20260918000000_add_scratch_cards
```

冒烟测试（会临时创建两个测试账号，一个有权一个无权，结束自动清理）：

```powershell
node ops/scripts/smoke-scratch.mjs
```

想拿一份 UTF-8 报告（Windows 控制台会把中文输出糊掉时很有用）：

```powershell
$env:SMOKE_REPORT="$env:TEMP\scratch-report.txt"; node ops/scripts/smoke-scratch.mjs
```

脚本覆盖：买票扣钱 → 余额与德州扑克 `/api/holdem/account` 一致（互通验证）→ 印刷层随票下发但 `outcome` 要刮开才有
→ 桌面坐标持久化 → 桌面容量上限 409 → 刮开结算（未达标 409 / 非法进度 400 / 幂等 / 统计只记一次 / 结算不发钱）
→ 兑奖机（未刮开与没中奖都 409、中奖票加钱、与德州余额一致、幂等、流水与统计）
→ 碎纸机（1 张 = 1 纸屑、槽位释放、幂等、纸屑流水、已碎的不能再兑奖）
→ 无权限账户 403 → 未登录 401 → 清理账号。

> `code/server/index.js` 不支持热更新：改完服务端代码要重启 `npm run dev` 才生效。
