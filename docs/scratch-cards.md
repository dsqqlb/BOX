# 刮刮乐小店（/tools/scratch-cards）

单人玩法：在商店买票 → 摆在桌子上（可拖）→ 点开像真票一样刮开涂层 → 中奖的拖进兑奖机换钱，
没中的拖进碎纸机变成纸屑；钱与纸屑两种货币用来升级刮刀、自动刮机器、兑奖机与碎纸机。

权限 slug：`scratch-cards`。页面 `/tools/scratch-cards`、接口 `/api/scratch/*`、
素材 `/image/scratch/*` 都要求该权限；别的工具不共享这张桌子的数据（单人、按账户隔离）。

长期回收率靠奖池概率（见下表）而不是靠玩家没钱来制造压力。

## 票种与玩法

票种、价格、奖池权重、格子布局全部在 `resources/content/scratch/tickets.json`；
服务端（`code/server/scratch-rules.js`）与客户端（`code/lib/scratch/catalog.ts`）读同一份文件，改数值不用改代码。

| 票种 key | 名称 | 票价 | 中奖方式 | 中奖率 | 平均奖金 | 长期回收率 | 解锁 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `three-match` | 三连金 | 10 | 刮出三个相同金额即中该金额 | 38% | 15.9 | ≈60% | 开局 |
| `lucky-symbol` | 好运符号 | 20 | 票面公布中奖符号，刮出三个即中奖 | 32% | 36.6 | ≈59% | 开局 |
| `high-low` | 比大小 | 30 | 3 组「你 vs 庄家」，赢 2 组中 30、赢 3 组中 150 | 42% | 56.4 | ≈79% | 开局 |
| `find-word` | 找中奖 | 5 | 9 格中给出 1~2 个「中奖」，出 1 个中 4、2 个中 15 | 50% | 5.7 | ≈57% | 开局 |
| `line-connect` | 连线 | 40 | 3×3 里任意一行 / 一列 / 一条对角线出现三个相同符号 | 22% | 107 | ≈58% | 票种保险柜 1 级 |
| `jackpot` | 头奖轮 | 20 | 6 格里只要出现一格「头奖」就拿走大奖 | 5% | 250 | ≈62% | 票种保险柜 2 级 |

> 表里的「平均奖金」与「长期回收率」由服务端按权重实时算出（`expectedReturn`），
> 商店卡片上也会显示，调数值时看它比看直觉可靠。

### 规则细节（防歧义设计）

- **三连金**：不中奖时每个金额最多出现两次，避免票面上「另一组也能三连」让人误判；
- **好运符号**：中奖符号以外的符号也最多两个；票面公布的中奖符号里**不含输赢信息**，刮开前就能看到；
- **比大小**：生成时直接避开平局，所以「赢了几组」永远不含糊；
- **找中奖**：整张票只在「中奖 / 谢谢参与」两种字之间分配，命中个数决定奖金档位。

## 界面与手感

- 页面是一屏布局，永不出现页面级滚动条：顶部货币条 + 左侧竖排商店 + 右侧桌面（兑奖机、碎纸机与自动刮奖机摆在桌面上，位置可拖）：
  - 手机竖屏（≤760px）时侧边栏收窄到 148px、机器缩小、机器说明与票面规则文字收起，仍是一屏；
- **商店在左侧竖向排列**，而且**只显示已解锁的票种**（没解锁的不占位置，列表底部提示还差几种）：
  - 四种票**一律是矩形**，靠长宽比与配色区分（不给票加锯齿、斜切、圆孔之类的外部轮廓）：
    三连金 = 宽横票（2.05 : 1）+ 金色；好运符号 = 竖票（0.72 : 1）+ 绿色；比大小 = 方票（1 : 1）+ 蓝色；找中奖 = 横票（1.45 : 1）+ 橙色；
    解锁后的连线 = 方票（紫）、头奖轮 = 横票（红金）；
  - 列表可滚动（只在侧边栏内部），所以以后加票种不会挤出屏幕。
- **桌面顶部是「能力」栏**：升级面板里带 `shelf` 标记且已点亮的节点会作为图标摆在这里，
  鼠标悬停或点一下看详情；详情里还会出现该物品的动作按钮：
  - 🛎️自动巡桌 → 一键刮开桌面所有未刮开的票；🧾自动兑奖 → 一键兑掉所有中奖票；♻️自动碎纸 → 一键碎掉所有没中奖的票；
  - ⚗️纸屑熔炼炉 → 把纸屑按当前汇率熔成钱（`POST /api/scratch/smelt`）；
  - 🔪刮刀 / 📐精准刮刀 / 🍀幸运护符 只显示数值；
  - **收起来的机器也放在这里**（见下面的「桌面机器」）：点一下就放回桌面，位置还是原来那个。
- **桌面机器（兑奖机 / 碎纸机 / 自动刮奖机）都能拖动**：按住机器拖到任意位置，松手写库（`POST /api/scratch/machines`）；
  右上角的小箭头能把机器收进「能力」栏（收起状态也存库，换设备一样）；机器位置横向夹在 9%~91%、纵向 18%~92%（百分比，指机器中心）。
- **机器的说明会跟着升级变**：碎纸机显示"1 张票 = N 单位纸屑"（N 含碎纸机加成），
  兑奖机显示"兑奖机加成 +x% · 暴击 y%"，自动刮奖机显示"约 x.x 秒一张（升级更快）"。
  聚焦大图下面的提示同样用升级后的数值（碎掉拿多少纸屑、兑奖到账多少、有没有暴击机会）。
- **机器特效**（纯视觉，都是直接改 DOM/class，不触发 React 重渲染）：
  - 兑奖机：整机闪一下金光 + 撒一把金币粒子 + 机器上方飘一行「+N 币」（暴击时同一套动画，飘字金额就是翻倍后的数）；
  - 碎纸机：机身抖一下 + 撒纸屑 + 飘一行「+N 纸屑」；
  - 自动刮奖机：机身抖着转、顶上进度条按升级后的速度走完（满级 = 立刻完成），刮完把票弹回桌面。
- **买票是「从商店扔出来」的，而且只有一段动作**：付完钱后票从左侧商店卡片的位置起手，**直线掠过**桌面落到桌面上
  （只有一个 0%→100% 的关键帧、不做抛物线上拱、也不做缩放弹跳），落点、初速度方向、路上自转、落地角度都是随机的；
  - 落地角度：刚买来的票 `rotation = null`，由票 id 算出一个随机角（`ticketRotation`），所以每张票角度都不一样、刷新后还是那个角；
  - **摆正规则**：票一旦被拖动或点开过，就会被摆正（`rotation = 0` 并写库），之后刷新也还是正的——拖过去摆好的票不会再歪着。
- **桌面上的票可以随手拖动**：按住拖到任意位置，松手时把 `posX/posY/z` 写回数据库。
  - 拖动期间**不触发任何 React 重渲染**（只改 DOM 的 left/top，松手才提交一次），而且指针事件挂在 `window` 上，
    所以不会掉帧、也不会出现「拖到一半拖不动」；
  - `TicketArt` 与商店卡片都套了 `React.memo`，其它状态变化（拖动高亮、弹窗开关）不会重画那堆票面 SVG；
  - 拿起来的票按时抬到最前；`z` 由服务端压在 20 以内（到顶就按叠放顺序重新编号 1..N），
    所以票永远不会盖住提示条、聚焦大票或升级面板；
  - 手指拖动不会被系统手势抢走（`touch-action: none`）；位置横向夹在 3%~97%、纵向 15%~97%（上方留给「能力」栏）；
  - 拖到兑奖机 / 碎纸机 / 自动刮奖机上机器会高亮，松手即结算（高亮也是直接改 class，不触发重渲染）。
- **点一下票（没有拖动）就聚焦刮奖**：票被放大成一张真票，其余界面退到模糊背景后面；
  已刮开的票再点开就是看结果，Esc 或点背景放回桌面。

## 刮开与揭晓（阶段 3）

- 聚焦视图是一张放大的矩形票（长宽比与桌上那张一致）：票头（票名 / 票价）→ 玩法说明（含票面公布的信息）
  → 游戏区（印刷格子 + 涂层）→ 票脚（刮开进度或结算）→ 动作按钮。
- **印刷层一直就在涂层下面**（这是手感的关键）：
  - 格子里的金额 / 符号 / 数字在买票时就随票下发（`ticket.print`），涂层只是盖在上面的一层 canvas；
  - 所以刮到哪就露出哪、**刮到的那一格会亮起来**（中奖格还会加一圈金光），而不是刮完才一起翻出来；
  - 服务端只保留「结算」：刮开进度达标后才确认中没中、多少钱（`ticket.outcome`），并据此决定能不能兑奖。
  - 「好运符号」的**中奖符号**属于印在票面上的公开信息，同样在 `print.legend` 里，刮开前就能看到。
- 刮开层是 `code/components/scratch/ScratchCanvas.tsx`：
  - 涂层由 canvas 画（渐变 + 斜纹 + 「用手指刮开涂层」提示），擦除用 `globalCompositeOperation = 'destination-out'`，
    笔刷是圆头线段，所以快速划也不会断成一串圆点；
  - 进度与**逐格进度**在同一个抽样循环里算出来（160ms 节流），逐格进度用来点亮已露出的格子；
  - 手机地址栏伸缩 / 旋屏导致尺寸变化时，把整张旧位图缩放贴回，已经刮掉的部分不会白刮；
  - 笔刷宽度来自 `scratch.brush`（占游戏区宽度的百分比），**阶段 5 的「刮刀升级」就是把它调大**。
- 结算流程：客户端刮到达标 → `POST /api/scratch/tickets/:id/reveal` → 服务端把状态改成 `scratched` 并首次下发 `outcome`
  → 涂层淡出、票脚出结果横幅、动作按钮出现。
- 安全边界（写清楚，免得以后把它误当成防作弊）：
  - 格子内容本来就在票上（真票也如此），客户端看得到不等于能改结果：中奖金额在买票时由服务端按种子定死；
  - `seed` 永不下发；钱的进出（买票、兑奖）全部由服务端确认并在同一个事务里落库；
  - 阈值只是手感门槛，服务端不校验手指是否真的划过（单人娱乐，跳过刮的动作没有收益）；
  - 重复 `reveal` 幂等：不重复计数，也不重复发奖；**结算不发钱**，钱要到兑奖机（阶段 4）才进账户。

## 票面外观（数据驱动，`shape` + `theme`）

票的形状、尺寸、配色全部写在 `resources/content/scratch/tickets.json`，客户端 `code/components/scratch/TicketArt.tsx` 只按配置画 SVG，**加一种长得不一样的票不需要写新组件**：

| 字段 | 作用 |
| --- | --- |
| `shape.aspect` | **票的长宽比**（宽 ÷ 高）：>1 横票、=1 方票、<1 竖票。票永远是矩形，形状差异只来自这里 |
| `shape.tableWidth` | 摆在桌面上时的宽度（桌面宽度的百分比） |
| `theme.accent` | 主题色（票名条、图案、卡片标题） |
| `theme.paper` / `theme.ink` | 纸面底色 / 印刷墨色 |
| `theme.foil` / `theme.edge` | 涂层金属色 / 描边色 |

`shape.kind` 只是给 CSS 和日志用的标签（`wide` / `tall` / `square` / `rounded`），不影响绘制。

票面上的图案也按玩法区分：三连金画三枚金币、好运符号画符号行（多于 3 个自动折两行）、比大小画两张号牌加 VS、
找中奖画 3×3 圆点阵、连线画 3×3 符号阵（中间一行点亮，暗示「连成一线」）、头奖轮画「头奖」圆章加几个 ✕。
票名、票价与「涂层未刮开」目前都是票面的一部分；阶段 3 会把涂层换成真正可刮的 canvas。

## 兑奖机与碎纸机（阶段 4）

桌子右上角是**兑奖机**，右下角是**碎纸机**；把票拖过去松手就算递交（机器会高亮）。聚焦视图里也有同样的按钮，
手机上不用拖来拖去。

| 机器 | 接受什么票 | 结果 |
| --- | --- | --- |
| 兑奖机 | 已刮开且中奖的票 | 奖金进「金钱」（与德州扑克同一份余额），状态 → `redeemed`，钱与票在同一个事务里落库 |
| 兑奖机 | 没刮开 / 没中奖的票 | 拒绝并说明原因（提示改用碎纸机），不会消耗票 |
| 碎纸机 | 任何未结算的票（已刮开或未刮开） | 产出纸屑（`shredScraps` 基础 1 + 「碎纸机」升级加成），状态 → `shredded` |
| 碎纸机 | 未刮开的票 | **先弹二次确认**（"碎掉就再也没机会中奖了"），可一键改为"先刮一下" |

- 结算成功后票离开桌面（`sealed` / `scratched` 才算桌面上的票），槽位随之释放，可以继续买新票。
- 碎纸会撒一把纸屑粒子（纯 CSS 动画，1.4 秒后自动清理，不留在 DOM 里）。
- 两个动作都是**幂等**的：重复调用返回 `alreadySettled: true`，不会重复给钱或多给纸屑；
  已经碎掉的票不能再兑奖，已经兑过奖的票不能再碎（都是 409）。
- 统计会累计：`redeemed`（兑奖次数）、`prizeTotal`（奖金总额）、`shredded`（碎纸张数）、`scrapsTotal`（纸屑总量）；
  流水里钱和纸屑分开记（`currency: money | scraps`）。

## 能力升级（阶段 5 上加的，阶段 8 改成折叠菜单）

节点、价格、效果全部写在 `resources/content/scratch/upgrades.json`（两端共用）。每个节点有：

| 字段 | 作用 |
| --- | --- |
| `category` | 分类（决定它落在哪个折叠菜单里、以及那一类的配色） |
| `column` / `row` | 布局坐标：`column` = 第几列、`row` = 这一列里的第几行。**阶段 8 起界面改成按分类折叠的下拉菜单，不再用坐标画图**；坐标仍由服务端下发（`maxColumn` / `maxRow`），留着给将来的别的视图用 |
| `requires` | 前置：`"scraper"` = 至少 1 级，`"scraper@3"` = 至少 3 级；前置没点亮就买不了（服务端也拦） |
| `shelf` | 点亮后会作为「能力」摆到桌面顶部的栏里（可带动作按钮） |
| `root` | 起点，开局就点亮，不参与购买、也不计入重置退款 |
| `effect` | 干什么（见下表），同一 `kind` 的多个节点会**累加** |
| `cost[i]` | 从 i 级升到 i+1 级的价格（金钱 + 纸屑，碎纸机 1 级不要纸屑，方便起步） |

当前 16 个节点（8 个分类）：
🎰 刮刮乐工坊（起点）→ 🔪 刮刀 →（3 级后）📐 精准刮刀；🤖 自动刮机器 →（3 级后）🛎️ 自动巡桌；
🏦 兑奖机 →（3 级后）🧾 自动兑奖；🗑️ 碎纸机 →（2 级后）⚗️ 纸屑熔炼炉 →（3 级后）♻️ 自动碎纸；
🏷️ 商店会员 →（2 级后）🛍️ 会员专柜；🍀 幸运护符 →（2 级后）💥 暴击；🔓 票种保险柜 →（2 级后）🎯 头奖信仰。

**交互**（`code/components/scratch/UpgradeAccordion.tsx`）：
- 每个分类是一行标题（图标 + 名称 + 「x / y 项点亮 · n%」+ 该类的进度条），**点标题展开/收起**，右上还有「全部展开 / 全部收起」；
- 第一次打开会自动展开"最有钱途"的那一类（有可解锁节点的第一组）；
- 每行一项能力：图标、名称、等级圆点、`现在 / 下一级` 文案、价格、状态标签（可解锁 / 资源不足 / 前置未点亮 / 已满级）；
- **点行尾「解锁」按钮立刻解锁**；**按住整行 3 秒**也行（行底会走一条进度条，松手太早取消）；
- 标题栏有 **一键重置**：点一下先弹出确认条（写明"清空多少级、退多少金钱与纸屑"），确认后
  `POST /api/scratch/reset` 把等级清空，并**按 `upgrades.json` 的价格表逐级复算、全额退还**已花的金钱与纸屑
  （等于洗点；起点不计价，所以不退它的"价格"）。退款额由 `computeRefund()` 统一算出——确认框里的数字和真正退款用的是同一份逻辑。

**效果种类与生效点**（服务端 `computeEffects` 算好后随 `profile.effects` / `catalog.effects` 下发，客户端只显示与使用）：

| `effect.kind` | 字段 | 生效点 |
| --- | --- | --- |
| `brush` | `base` + `perLevel` | 聚焦视图刮开层的笔刷宽度（**开局只有 12%**，升满能到 50% 以上） |
| `threshold` | `perLevel`（负数） | 结算门槛：`reveal` 时按 `票种门槛 + thresholdBonus` 判定（最低 15%） |
| `auto` | `base` + `perLevel` + `machineBaseMs` / `machinePerLevelMs` | 两条路：① 聚焦视图的「开自动刮」（每秒 `perLevel × 等级` 点）；② **桌面自动刮奖机**的耗时 = `max(0, machineBaseMs - machinePerLevelMs × 等级)` 毫秒（1 级 4.1 秒，满级 0 = 立刻完成） |
| `prizeBonus` | `perLevel` | 兑奖结算：`到账 = round(票面奖金 × (1 + 加成))` |
| `crit` | `perLevel` + `multiplier` | 兑奖时按概率把这次奖金 ×`multiplier`（结果写进流水备注） |
| `shredBonus` | `perLevel` | 碎纸产出：`shredScraps + 加成` |
| `exchange` | `base` + `perLevel`（负数） | 纸屑熔炼汇率：每 N 单位纸屑换 1 币（0 = 未解锁，对应 `POST /api/scratch/smelt`） |
| `discount` / `tableSlotsPerLevel` | `perLevel` / `tableSlotsPerLevel` | 买票实付价 / 桌面容量上限（多条折扣线会累加，上限 50%） |
| `luck` | `perLevel` | 买票时生成票面的中奖概率（只覆盖本张票，不改共享配置对象） |
| `ticketLuck` | `ticket` + `perLevel` | 只对指定票种叠加中奖率（例如「头奖信仰」只加「头奖轮」） |
| `unlock` | `unlockByLevel` | 解锁票种：商店目录的 `unlocked` + 买票时的服务端校验 |
| `flag` | `flag` | 给客户端功能当开关，例如 `autoScratchAll` 打开「自动巡桌」的一键刮开按钮 |
| `none` | — | 纯节点（树的起点） |

### 想加一个新升级？三步，不用改前端

1. 在 `upgrades.json` 的 `upgrades` 里加一个节点：`id` / `name` / `icon` / `category` / `column` / `row` / `requires` / `maxLevel` / `cost` / `effect`；
2. 如果效果是已有的 `kind`，到这里就结束了（例如再加一条「折扣」线：`{ "kind": "discount", "perLevel": 0.03 }`，会自动和会员折扣累加）；
3. 如果要**全新种类**的效果：JSON 里照样写 `kind` + `perLevel`，然后
   - 在 `code/server/scratch-store.js` 的 `computeEffects` 里加一个 `case`，在 `describeEffect` 里加一句人话；
   - 未识别的 `kind` 不会报错：会原样累加进 `effects.custom`，可以先在 JSON 里试数值，前端也能读到。
4. 想让节点额外出现在桌面的「能力」栏：加 `"shelf": true`（图标与说明直接复用节点字段）。

- `computeEffects(levels)` 是**唯一**的效果计算入口，技能树面板上的「现在 / 下一级」文案也由它派生，所以调数值只改 JSON。
- 解锁与买票、兑奖共用同一条筹码写入路径（`applyChipsWithinTx`）：金钱、纸屑、等级、流水在**一个事务**里完成。
- **前置与解锁都在服务端把关**：直接构造 `POST /api/scratch/upgrade { id: 'precision' }` 会被 409（前置没点亮），
  直接买未解锁票种也会 409 —— 不是只把界面画灰。

## 素材

- 目前**零外部素材**：票面（`TicketArt.tsx`）、三台机器（`MachineArt.tsx`：兑奖机 / 碎纸机 / 自动刮奖机）、纸屑与金币粒子都是程序化 SVG / CSS，
  所以没有版权问题、缩放不糊，也不用往仓库里塞图片。
- 想换成真实图片：把 PNG 放进 `resources/public/image/scratch/`（该目录已映射到 `scratch-cards` 权限，静态托管会自动放行并做缓存），
  然后把组件里的 `<svg>` 换成 `<img src="/image/scratch/xxx.png" className={className} alt="" />` 即可。

## 服务端设计

- 结果**在买票那一刻**就按种子生成并存进 `ScratchTicket.resultJson`：
  随机数 = `crypto` 摘要 + xorshift128，同一个 seed 永远生成同一张票（可复现、可审计）。
- `seed` 与未刮开的 `resultJson` **绝不下发**给客户端（`status = sealed` 时 DTO 里 `result` 恒为 `null`），
  所以改前端刷不出奖；刮开、兑奖、碎纸都将是服务端动作。
- 钱、票、流水在**同一个 `prisma.$transaction`** 里完成：扣钱走 `holdem-store.applyChipsWithinTx`
  （筹码账户唯一写入路径），所以不会出现「钱扣了票没生成」。
- `ScratchLedger` 额外记一份刮刮乐自己的流水（含钱的镜像），用于在界面里看本工具的收支历史。

### 数据表（Prisma / SQLite）

| 表 | 作用 |
| --- | --- |
| `ScratchProfile` | 一人一行：`scraps`（纸屑）、`levelsJson`（升级等级）、`unlockedJson`（显式解锁的票种）、`statsJson`、`machinesJson`（三台机器的位置与收起状态） |
| `ScratchTicket` | 一行 = 桌面上的一张票：`kind / price / seed / resultJson / status / scratchRatio / posX / posY / z / rotation`（`rotation` = null 表示"刚扔出来还没摆正"，0 表示已摆正） |
| `ScratchLedger` | 流水：`currency`（money / scraps）、`delta`、`balance`、`kind`、`ticketId`、`note` |

`ScratchTicket.status` 取值：`sealed`（未刮开）→ `scratched`（已刮开）→ `redeemed`（已兑奖）/ `shredded`（已碎）。

### 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/scratch/profile` | 余额（= 筹码）、纸屑、升级等级、解锁、统计、桌面槽位 |
| GET | `/api/scratch/catalog` | 票种配置 + 期望回收率 + 是否解锁 + 配置问题 |
| GET | `/api/scratch/ledger` | 本工具流水（最近 50 条） |
| GET | `/api/scratch/tickets` | 桌上的票（未结算的；未刮开的票不含答案） |
| POST | `/api/scratch/tickets` | 买票 `{ kind }`：事务扣钱 + 生成票面 + 落库，返回票与新余额 |
| PATCH | `/api/scratch/tickets/:id` | 保存桌面坐标与摆放角度 `{ posX, posY, z, rotation }`（拖动松手时写入；`rotation: 0` = 摆正） |
| POST | `/api/scratch/tickets/:id/reveal` | 刮开结算 `{ scratchRatio }`：进度达标才确认结算；未达标 409，重复调用幂等 |
| POST | `/api/scratch/tickets/:id/redeem` | 兑奖：只接受「已刮开且中奖」的票，奖金进与德州扑克共用的余额 |
| POST | `/api/scratch/tickets/:id/shred` | 碎纸：产出纸屑（1 张 = 1 + 升级加成），未刮开的也能碎 |
| GET | `/api/scratch/upgrades` | 升级面板：分类、等级、下一级价格、是否买得起、效果文案，以及 `refundPreview`（现在重置会退多少） |
| POST | `/api/scratch/upgrade` | 升一级 `{ id }`：金钱 + 纸屑在同一事务里扣；满级 / 前置未点亮 / 资源不足都 409 |
| POST | `/api/scratch/reset` | **一键重置**：清空所有等级，并按价格表全额退还已花的金钱与纸屑（同一事务；没有等级时 409） |
| POST | `/api/scratch/machines` | 保存机器状态 `{ id, x?, y?, folded? }`：`id ∈ redeem / shred / auto`，未知 404；返回最新布局 |
| POST | `/api/scratch/smelt` | 纸屑熔炼 `{ scraps? }`：按当前汇率换钱（不传数量 = 全部熔掉）；未解锁 409 |

写操作都要求同源请求；账户没有 `scratch-cards` 权限时统一 403。
