# Kards 二战卡牌（组卡器 + 双人对战桌）

路径：`/tools/kards`

## 定位

这个工具不是"替你打牌的游戏"，而是一张**数字牌桌**（类似 Tabletop Simulator）：

- 卡图来自本地资源 `public/image/Kards`，共 1600+ 张，按`阵营/费用`目录组织；
- 卡面上的数值、类型、效果文字以图片形式呈现，**服务端不解析、不判定任何规则**；
- 抽牌、出牌、攻击、防御、结算全部由玩家手动操作，模拟器只负责把牌摆好、同步到对面。

## 组卡器

- 浏览全部卡牌：按阵营、费用（kredits 0–7）筛选，按中文/英文卡名搜索；
- 点击卡牌加入当前草稿，同名牌最多 3 张、草稿最多 100 张（服务端上限 200）；
- 低于 40 张只做提示，不强制；
- 牌组按账户保存在 SQLite（`KardsDeck` 表，卡片存为卡牌 id 数组，重复 id 表示多张）；
- 「用这副牌开局」直接把当前草稿带进对战桌。

## 对战桌

- 进入「对战桌」页先看到**公共房间大厅**（像先攻追踪器主屏一样是公共服务）：
  - 自动列出所有进行中的房间（房间号、房主、人数/在线数、活跃时间），每 5 秒刷新；
  - 等待对手的房间可直接点「加入」，对局中的房间显示为锁定；
  - 也可以自己选好出战牌组点「创建房间」，或在右侧输入 6 位房间号加入；
  - 打开别人分享的 `/tools/kards?room=XXXXXX` 链接会自动跳到大厅并预填房间号。
- 房主点「创建房间」生成 6 位房间号；对方按房间号加入或从列表加入；
- 两名玩家通过 WebSocket 实时同步同一张桌子：客户端连接 `/ws`（带 `?kards=1` 标记，与先攻追踪器共用同一条通道，代理/隧道只需转发 `/ws`；`/ws/kards` 路径仍兼容）；
- 战场布局与 Kards 一致：**中间三条横排——敌方支援阵线 / 共享前线 / 我方支援阵线**，HQ 在各自支援阵线的左侧格，牌库/墓地以叠放形式在右侧，手牌在下方（对手在顶部，只显示牌背）；
- 隐私规则：自己的手牌和牌库对对手保密（对手只看到牌背和数量）；HQ、前线、支援、墓地公开；
- 操作方式：
  - **拖拽**：把自己的牌拖到任意自己的区域；
  - **双击**：翻面/翻开；
  - **右键**：翻面、旋转（攻击/防御）、伤害 ±1、回手牌、移到前线/支援/HQ、弃置、放回牌库；
  - **按钮**：抽 1/3/7、洗牌、移交回合、重置桌面、kredits ±1。
- 房间为进程内存状态：服务器重启会清空，无活动 2 小时后自动回收；断线可凭同一账号重新加入原房间。

> 提示：`server/index.js` 不支持热更新，改完服务端代码后需要重启 `npm run dev` 才能生效；连接失败时对战桌会显示红色横幅并给出排查提示。

## 数据与部署

卡牌目录由脚本生成：

```powershell
npm run build:kards
```

该命令扫描 `public/image/Kards`，输出 `data/kards/cards.json`（id/名称/阵营/费用/图片路径）。新增或改名卡图后重新运行一次即可。

牌组存 SQLite，运行 `npm run db:setup`（或至少 `db:generate` + `db:migrate`）后生效。

权限 slug：`kards`（页面、`/api/kards/*`、`/ws/kards`、`/image/Kards/*` 均要求该权限）。

## 冒烟测试

```powershell
npm run build
node scripts/smoke-kards.mjs
```

脚本会临时创建两个测试账号，拉起生产服务，验证卡牌目录/牌组 API 与双人 WebSocket 全流程（含手牌隐私遮蔽），结束后自动清理账号并关闭服务。
