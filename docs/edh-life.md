# 万智牌 EDH 记血器

路径：`/tools/edh-life`。2~4 人的指挥官赛记血器，为**一张方桌四个人面对面坐**的场景设计：2×2 中心对称，第二排整体旋转 180°，坐在对面的人看自己的数字是正的。

## 界面与操作

| 操作 | 效果 |
| --- | --- |
| 点色块**左半** | 生命 −1 |
| 点色块**右半** | 生命 +1 |
| **按住**左半 / 右半 **1 秒** | 生命 −5 / +5；**继续按住则每 0.55 秒再 −5 / +5**（热区底部进度线扫满即进入持续状态；中途松手只算单击 ±1） |
| 按住**大数字所在的中央区域** 2 秒 | 打开「掉血 / 回血任意数值」弹窗（掉血与回血合并成一个弹窗，可切换、实时预告结果）。单击中央**不做任何事**，避免误触 |
| 点色块下方的**记录**按钮 | 打开该玩家的记录弹窗；已经有值的项目显示在上方，可从下方继续添加其他项目 |
| 点玩家名字 | 改名（最多 16 字） |

**左右按屏幕上的视觉位置判定**：正座位是左边减血、右边加血；对面座位整体旋转 180°，所以屏幕左边变成加血、右边变成减血。这样从当前屏幕看，左上角／右上角座位的操作方向也保持一致。

中央那块区域是**完全隐形**的（没有边框、没有背景、没有提示文字），只有按住满 2 秒才弹窗；它只居中占一块正方形，左右的 ±1 依然覆盖其余整块宽度。

色块下方只有一个**记录**入口，不再常驻铺开六个计数器。记录弹窗会跟随点击玩家的座位朝向打开；当前值为正的项目才显示在「当前记录」，值为 0 的项目回到「添加记录」。所有弹窗右上角都有旋转按钮，每点一次整体旋转 180°，方便坐在不同方向的人阅读；**按钮大小**用设置里的「图标」滑块调整（锚点固定在右上角，放大只往左下长），每个弹窗**上次退出时朝向哪边，下次打开就还是哪边**。

**判负**：生命 ≤ 0 或中毒满 10 → 该色块整体灰化（`grayscale`）+ 中央显示骷髅头与出局原因。条件解除（例如回血、减中毒）会自动复活，方便误判回退。

## 中间缝隙（公共工具条）

只有**一排**，贴着当前视角（对面那一排旋转 180° 后看到的是同一排的镜像，读数正常）：

- ⚙ 设置
- 🎲 骰子（预设骰式 + 自定表达式）
- 🪙 硬币
- 🕘 掷骰历史
- 计时中 / 已暂停（点击切换；这就是一个独立的小秒表，不和任何「对局」绑定，时长数字在设置里）
- 数据同步状态灯

按钮是毛玻璃圆角矩形，带一道周期性扫过的流光。色块里没有骰子/硬币/历史按钮——它们是公共的。

## 对局状态（没有存档）

这一版**取消了存档系统**：一个账户只有一份状态，就是「当前这张桌子」，记血时随时同步到服务器。没有开始/结束对局，没有存档列表，也不能读档。

| 位置 | 操作 | 作用 |
| --- | --- | --- |
| 中间缝隙 | 计时中 / 已暂停 | 独立的小秒表，点一下切换走/停，不参与任何胜负判定 |
| 设置 → 对局 | **重新开始对局** | 所有玩家的血量回到起始值、六个计数器清零、出局状态解除（名字与配色保留），回合回到 1，掷骰历史清空 |
| 设置 → 计时 | 暂停/继续、回合 ± | 手动控制秒表与回合数 |

- **重新开始对局不动计时器**：秒表要停要走在中间缝隙点。
- **重新开始对局不会产生新记录**：状态仍然写回同一条（`id` 不变），数据库里永远只有这个账户的一份当前状态。
- **离开页面（切走 / 刷新 / 关页）会自动暂停计时**，回来点中间缝隙的计时按钮继续。
- 想清空历史、回到全新一桌，就用「重新开始对局」。


## 骰子与硬币

复用先攻追踪器主屏的同一套 3D 引擎（`components/dnd/DiceRoller` + `dice-box-threejs`，Three.js + cannon-es 物理）：

- **结果面板上下各一份**，下面那份旋转 180°，四个方向都能读到；
- 收起方式两种：**7 秒后自动消失**，或**点击屏幕任意处立即消失**（收起不会重新投掷）；
- 骰盘**常驻挂载并在进页面时预热**；
- 骰子弹窗里只有预设骰式（默认 `1d20`、`1d6`，可在设置里增删改）和「输入任意表达式」；**表达式用自绘键盘输入，页面里没有任何输入框**，所以移动端不会弹出系统键盘；
- 硬币是引擎内置的硬币骰，两面是我们自己画的**金色数字「1」「2」**，投掷力度标记为 `1d2!!!` 以获得快速多次翻转的观感。

> 关于硬币贴图：骰子引擎加载贴图时会无条件在路径前拼上 `assetPath`（`/dice-assets/`），所以运行时塞 data URL 是行不通的；上游的 silvercoin 素材又没有随 vendored 拷贝进入本项目。因此这里用纯 Node（zlib + 手写 PNG 分块）生成四个真实文件：`heads.png`（太阳）、`tail.png`（数字 1）及各自的 `_bump`。需要重新生成时执行 `node ops/scripts/generate-coin-textures.mjs`。

### 骰子引擎的两个坑（改动这块前先读）

引擎自带的表达式解析器（`dice-box-threejs/DiceNotation.js`）能力有限，本项目靠 `lib/diceExpression.ts` 在它之上补齐。两个必须注意的点：

1. **`kh/kl` 取高取低引擎不认识。** 直接把 `2d20kh1` 交给引擎，它会把 `kh1` 当成未知骰型，抛 `dice type unavailable` 并在取结果时连带崩在 `Cannot read properties of undefined` 上。正确做法是三步：`parseDiceExpression` 解析 → 只把纯 `NdS` 交给引擎摇 → 引擎返回原始点数后用 `evaluateRecipe` 重新分账（被丢弃的骰子划线变灰，总计按保留的骰子算）。
2. **裸常数不能交给引擎。** 引擎解析器会把 `3d6+2` 里的 `2` 当成"这个骰子组施加几次"，于是变成摇 3d6 两次；引擎自己也把"修正值"实现成了"几个面"（`2d6+3` 会被当成掷 2 个 d3）。所以本工具自己拼引擎表达式：骰子部分用 `flattenExpression`，常数部分用 `flattenToRecipe().modifierConstant` 以带符号纯数字追加在末尾（引擎对"一个带符号的纯数字"会正确算成修正值）。

这两点都在 `/tools/edh-life` 内部处理，没有改动共享的 `lib/diceExpression.ts` 和先攻追踪器主屏的行为。

非法表达式（例如 `2d20kh1+`）会在弹窗里直接给出提示，不会丢给引擎。

骰子结果是**真随机**：`Math.random` 在浏览器端，没有服务端干预，也没有任何"作弊"逻辑。

## 数据与持久化

两层，互不阻塞：

1. **localStorage**（立即生效）：`edh-life-current` 记住当前这条状态，刷新页面自动恢复（血量、计数器、掷骰历史、回合、出局状态、计时累计）。
2. **SQLite**（防抖同步，约 700ms）：一个账户**一条** `EdhLifeGame` 记录，`stateJson` 是完整快照；座位（`EdhLifePlayer`）另外成行便于统计。页面加载时用 `GET /api/edh-life/games/running` 恢复；服务器上还没有记录时自动 `POST` 建一条，之后一直 `PATCH` 同一条。

服务端不可用（未登录、断网、接口报错）时只降级为"仅本机保存"，界面右下角会显示 ⚠，**不会因为同步失败而丢掉本地这张桌子**。

### 表结构

| 表 | 说明 |
| --- | --- |
| `EdhLifeGame` | 一个账户一条：`title`、`playerCount`、`startingLife`、`round`、`status`、`startedAt`、`durationSeconds`、`stateJson`（完整快照，含计时与掷骰历史） |
| `EdhLifePlayer` | 每个座位一行：`seat`、`name`、`color`、`life`、`poison`、`energy`、`treasure`、`clue`、`food`、`experience`、`eliminated`、`eliminatedReason` |
| `EdhLifeRoll` | **历史遗留表**：旧版本的掷骰记录还留在库里，新版本不再写入（掷骰历史改为随快照同步） |

`EdhLifePlayer` 随 `EdhLifeGame` 级联删除。


## 接口

全部按账户隔离，写操作要求同源（`Origin` 与 `Host` 一致）：

| 方法与路径 | 说明 |
| --- | --- |
| `POST /api/edh-life/games` | 第一次使用时建这条「当前状态」记录 |
| `GET /api/edh-life/games/running` | 取当前状态（页面加载时恢复；一个账户最多一条未结束记录） |
| `PATCH /api/edh-life/games/:id` | 保存状态（座位按 `seat` upsert，人数减少时自动清理多余座位） |

没有列表、读档、删除与「掷骰单表」接口——存档相关的功能已经从产品里去掉。

权限 slug 是 `edh-life`。注意 `code/server/http-utils.js` 里的判断顺序：`/api/edh-life/` 必须排在 `/api/edh/`（EDH 组卡台）之前，否则会被误判成 `edh-builder`。

## 移动端与手势

长按是本工具的核心操作，所以页面会主动关掉所有会抢走长按的系统行为：

- `DisableZoom`：禁双指捏合与 iOS 原生手势缩放；
- 页面上 `touch-action: manipulation`、`user-select: none`、`-webkit-touch-callout: none`、`overscroll-behavior: none`：禁双击缩放、禁文本选择、禁长按弹出系统菜单、禁下拉刷新；
- 所有交互按钮都 `preventDefault` 并抑制 `contextmenu`。

布局用 `dvh` 与百分比，**任何屏幕尺寸都一屏显示，不出现滚动条**；横向用 `clamp()` 控制字号，手机上血量数字仍保持 40px 以上，±1 热区宽度不小于 44px。

## 备份

`resources/data/box.sqlite` 含每个账户的当前状态（以及旧版本留下的存档与掷骰记录），随 `resources/data/` 一起备份即可（见 [部署指南](./deployment.md) 第 13 节）。localStorage 只是本机快照，换设备后靠服务器恢复。
