# 万智牌 EDH 记血器

路径：`/tools/edh-life`。2~4 人的指挥官赛记血器，为**一张方桌四个人面对面坐**的场景设计：2×2 中心对称，第二排整体旋转 180°，坐在对面的人看自己的数字是正的。

## 界面与操作

| 操作 | 效果 |
| --- | --- |
| 点色块**左半** | 生命 −1 |
| 点色块**右半** | 生命 +1 |
| **按住**左半 / 右半 **1.5 秒** | 生命 −5 / +5；**继续按住则每 0.55 秒再 −5 / +5**（热区底部进度线扫满即进入持续状态；中途松手只算单击 ±1） |
| 按住**大数字所在的中央区域** 3 秒 | 打开「掉血 / 回血任意数值」弹窗（掉血与回血合并成一个弹窗，可切换、实时预告结果）。单击中央**不做任何事**，避免误触 |
| 点计数器徽章 | 该计数器 +1 |
| **按住**计数器徽章 | 该计数器 −1 |
| **双击 / 右键**计数器徽章 | 输入任意数值 |
| 点玩家名字 | 改名（最多 16 字） |

**左右是按色块自己的坐标系判定的**：色块整体按座位旋转了 180°，所以坐在对面的人点他视角的左边，就是左边——不需要额外镜像，也不会出现"对面左右相反"。

中央那块区域是**完全隐形**的（没有边框、没有背景、没有提示文字），只有按住满 3 秒才弹窗；它只居中占一块正方形，左右的 ±1 依然覆盖其余整块宽度。

色块下方一行是六个常用计数器：**能量、珍宝、线索、食物、中毒、经验**，毛玻璃圆角方块。

**判负**：生命 ≤ 0 或中毒满 10 → 该色块整体灰化（`grayscale`）+ 中央显示骷髅头与出局原因。条件解除（例如回血、减中毒）会自动复活，方便误判回退。

## 中间缝隙（公共工具条）

只有**一排**，贴着当前视角（对面那一排旋转 180° 后看到的是同一排的镜像，读数正常）：

- ⚙ 设置
- 🎲 骰子（预设骰式 + 自定表达式）
- 🪙 硬币
- 🕘 掷骰历史
- 计时中 / 已暂停（点击切换；**时长数字在设置里**）
- 数据同步状态灯

按钮是毛玻璃圆角矩形，带一道周期性扫过的流光。色块里没有骰子/硬币/历史按钮——它们是公共的。

## 对局与存档

**一次开始 → 一次结束 = 一条存档**；对局过程中只记录，不产生存档。

| 按钮 | 作用 |
| --- | --- |
| **开始对局** | 开始计时。点下去之后**设置面板外圈会出现红色流光**，一眼能看出这局正在记录 |
| **结束对局** | 封存这一局（写入时长、胜者、完整快照），计时停止，红色流光消失 |
| **保存并重置** | 先封存当前这局，再直接开一局全新的 |
| **查看 / 删除存档** | 列出所有已封存的存档，可读档继续，也可删除（删除有确认弹窗） |

- **离开页面（切走 / 刷新 / 关页）会自动暂停计时**，回来点「开始对局」继续。
- 存档时长在结束那一刻**冻结**，之后不会再增长。
- 读档会用存档里的时长继续计时。

## 骰子与硬币

复用先攻追踪器主屏的同一套 3D 引擎（`components/dnd/DiceRoller` + `dice-box-threejs`，Three.js + cannon-es 物理）：

- **结果面板上下各一份**，下面那份旋转 180°，四个方向都能读到；
- 收起方式两种：**7 秒后自动消失**，或**点击屏幕任意处立即消失**（收起不会重新投掷）；
- 骰盘**常驻挂载并在进页面时预热**；
- 骰子弹窗里只有预设骰式（默认 `1d20`、`1d6`，可在设置里增删改）和「输入任意表达式」；**表达式用自绘键盘输入，页面里没有任何输入框**，所以移动端不会弹出系统键盘；
- 硬币是引擎内置的硬币骰，两面是我们自己画的**金色数字「1」「2」**，投掷力度标记为 `1d2!!!` 以获得快速多次翻转的观感。

> 关于硬币贴图：骰子引擎加载贴图时会无条件在路径前拼上 `assetPath`（`/dice-assets/`），所以运行时塞 data URL 是行不通的；上游的 silvercoin 素材又没有随 vendored 拷贝进入本项目。因此这里用纯 Node（zlib + 手写 PNG 分块）生成四个真实文件：`heads.png`（太阳）、`tail.png`（数字 1）及各自的 `_bump`。需要重新生成时执行 `node scripts/generate-coin-textures.mjs`。

### 骰子引擎的两个坑（改动这块前先读）

引擎自带的表达式解析器（`dice-box-threejs/DiceNotation.js`）能力有限，本项目靠 `lib/diceExpression.ts` 在它之上补齐。两个必须注意的点：

1. **`kh/kl` 取高取低引擎不认识。** 直接把 `2d20kh1` 交给引擎，它会把 `kh1` 当成未知骰型，抛 `dice type unavailable` 并在取结果时连带崩在 `Cannot read properties of undefined` 上。正确做法是三步：`parseDiceExpression` 解析 → 只把纯 `NdS` 交给引擎摇 → 引擎返回原始点数后用 `evaluateRecipe` 重新分账（被丢弃的骰子划线变灰，总计按保留的骰子算）。
2. **裸常数不能交给引擎。** 引擎解析器会把 `3d6+2` 里的 `2` 当成"这个骰子组施加几次"，于是变成摇 3d6 两次；引擎自己也把"修正值"实现成了"几个面"（`2d6+3` 会被当成掷 2 个 d3）。所以本工具自己拼引擎表达式：骰子部分用 `flattenExpression`，常数部分用 `flattenToRecipe().modifierConstant` 以带符号纯数字追加在末尾（引擎对"一个带符号的纯数字"会正确算成修正值）。

这两点都在 `/tools/edh-life` 内部处理，没有改动共享的 `lib/diceExpression.ts` 和先攻追踪器主屏的行为。

非法表达式（例如 `2d20kh1+`）会在弹窗里直接给出提示，不会丢给引擎。

骰子结果是**真随机**：`Math.random` 在浏览器端，没有服务端干预，也没有任何"作弊"逻辑。

## 数据与持久化

两层，互不阻塞：

1. **localStorage**（立即生效）：`edh-life-games` 存最近 20 局，`edh-life-current` 记住当前局。记血是"点一下就要有反应"的操作，绝不等待网络；刷新页面自动恢复当前对局（含血量、计数器、掷骰历史、回合、出局状态）。
2. **SQLite**（防抖同步，约 700ms）：一局对战 = 一条记录，含开始时间、时长、结束时间、每人最终血量与六个计数器、以及完整状态快照。

服务端不可用（未登录、断网、接口报错）时只降级为"仅本机保存"，界面右下角会显示 ⚠，**不会因为同步失败而丢掉本地这局**。

### 表结构

| 表 | 说明 |
| --- | --- |
| `EdhLifeGame` | 一局对战：`title`、`playerCount`、`startingLife`、`round`、`status`、`winnerSeat`、`startedAt`、`endedAt`、`durationSeconds`、`stateJson`（完整快照） |
| `EdhLifePlayer` | 每个座位一行：`seat`、`name`、`color`、`life`、`poison`、`energy`、`treasure`、`clue`、`food`、`experience`、`eliminated`、`eliminatedReason` |
| `EdhLifeRoll` | 每次掷骰一行：`at`、`source`（dice/coin）、`notation`、`total`、`seat`、`detailJson`（每颗点数） |

`EdhLifePlayer` 与 `EdhLifeRoll` 都随 `EdhLifeGame` 级联删除；每局最多保留最近 500 条掷骰记录。

## 接口

全部按账户隔离，写操作要求同源（`Origin` 与 `Host` 一致）：

| 方法与路径 | 说明 |
| --- | --- |
| `GET /api/edh-life/games` | 历史列表（摘要，不含整包快照） |
| `POST /api/edh-life/games` | 开一局新对战 |
| `GET /api/edh-life/games/running` | 最近一局未结束的对局（页面加载时恢复用） |
| `GET /api/edh-life/games/:id` | 单局详情（含快照） |
| `PATCH /api/edh-life/games/:id` | 保存状态（座位按 `seat` upsert，人数减少时自动清理多余座位） |
| `DELETE /api/edh-life/games/:id` | 删除一局 |
| `GET /api/edh-life/games/:id/rolls` | 掷骰历史（最近 N 条） |
| `POST /api/edh-life/games/:id/rolls` | 追加一条掷骰记录 |

权限 slug 是 `edh-life`。注意 `server/http-utils.js` 里的判断顺序：`/api/edh-life/` 必须排在 `/api/edh/`（EDH 组卡台）之前，否则会被误判成 `edh-builder`。

## 移动端与手势

长按是本工具的核心操作，所以页面会主动关掉所有会抢走长按的系统行为：

- `DisableZoom`：禁双指捏合与 iOS 原生手势缩放；
- 页面上 `touch-action: manipulation`、`user-select: none`、`-webkit-touch-callout: none`、`overscroll-behavior: none`：禁双击缩放、禁文本选择、禁长按弹出系统菜单、禁下拉刷新；
- 所有交互按钮都 `preventDefault` 并抑制 `contextmenu`。

布局用 `dvh` 与百分比，**任何屏幕尺寸都一屏显示，不出现滚动条**；横向用 `clamp()` 控制字号，手机上血量数字仍保持 40px 以上，±1 热区宽度不小于 44px。

## 备份

`data/box.sqlite` 含全部对局历史，随 `data/` 一起备份即可（见 [部署指南](./deployment.md) 第 13 节）。localStorage 只是本机快照，换设备后靠服务器恢复。
