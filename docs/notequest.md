# NoteQuest 地牢笔记

路径：`/tools/notequest`。这是一个把单人 PNP 桌游 **NoteQuest（核心规则书）** 搬到浏览器里的模块：一个人、一支铅笔、几个 D6 掷出地牢，只是这次地图、表格与掷骰都由程序来记。需要 `notequest` 权限。

规则数据来自项目根目录 `参考文件/1.NoteQuest_cn.pdf`（原作者 Tiago Junges，中文版译者 JungleZL），是**按表格逐条录入**的，不是概括改写。

## 功能

- **人物池**：有一个独立的人物界面，可以「掷骰建角」（2d6 种族 + 2d6 职业，咒语按能力掷）也可以「自定义建角」（自己挑种族/职业/咒语、起名、决定开局火把与金币）。首页人物卡上直接有两个入口（掷骰 / 自定义），每张卡还能点「自定义」再改名字、种族、职业、装备咒语——改的是人物池里的那一位，存档与遗体不受影响。建好的角色存进按账户隔离的人物池，之后任意一局都能挑其中一个带进地牢；角色死了就永久消失（遗体留在地牢里），战绩（下过几次、死过几次）会记在人物卡上。
- **三个存档栏位**：一个账号最多三个存档位，首页第一块就是三张存档卡（显示进行中的那一局、各类数据条数、更新时间），顶栏也有一排 `存档 ①②③` 可以随时切换。**一个栏位里做的任何事——存档、人物池、永久地牢、墓地——都只属于这个栏位**；切走就是整套换掉，互不干扰，也可以单独「清空栏位」。
- **永久地牢**：一个栏位 × 一种地牢类型 = 一张**永久地图**。开门探索出来的片段、房间内容、怪物、宝箱与密道都会写回这张图，换个角色再进来看到的还是上次画到哪儿就是哪儿（同一类型的名字也一直跟着这张图）。
- **遗体与掉落**：角色死在哪里，遗体就留在哪个房间，背包里的物品、身上的护甲与武器、没花掉的金币与财宝全部留在原地；后来进入这座地牢的角色可以「能拿的都拿走」或逐件取走（背包满了的会留在遗体上）。
- **格子地图**：地图是画在虚线格子上手绘风格的平面图。小房间 2×2、中房间 3×3、宽房间 4×3、大房间 4×4，走廊 1×1，入口/楼梯 2×2，最终房间 4×4。**相邻的房间就是墙贴墙紧挨着**：新片段一定贴在父片段（或同层别的房间）的墙上生成，不会出现孤零零飘在空地上的屋子。地图可用**鼠标拖拽平移、滚轮缩放**（工具条上有 −/+/复位 与当前比例）。
- **墙上的门**：每个片段一生成就有门，门是**墙上加粗的一格门框**，直接画在它所在的那面墙上；**一间房的一面墙最多只有一扇门**（同一面墙上的门会被挪到空墙去）。相邻两间房的门开在同一格里、**重叠在一起**，所以两边都能点、都能来回走：关闭 = 木门板、锁住 = 红门板 + 锁扣、砸开 = 碎裂门板、打开 = 门框 + 开着的门扇（墙真的会断开成缺口）。已经探索过的房间随时可以回来重进。
- **自动探索**：开门即探索。点门掷「开门表」（1 = 陷阱、2-3 = 锁住、4-6 = 没锁）；没锁时继续掷对应列（从楼梯 / 从走廊 / 从房间）的「地牢片段表」。地图上会给怪物数量、宝箱、密道、遗体、当前小人分别打标记，没进去过的房间是虚线幽灵；房间名/尺寸/门数与「？未探索」画在房间里侧。
- **掷骰全记录**：任何一次掷骰（决定地牢名、房间内容、开门、搜刮、察觉判定…）都会在 3D 骰子画面上写明**「为了什么」+ 骰式 + 每一颗骰子 + 合计**；回放结束后，同一批结果还会留在房间面板的**「掷骰记录」**里（最新的在前，可收起），所以任何时候都能翻出「刚才那 6 是为什么掷的」。
- **分块界面**：进入地牢后画面分成四块 —— 地图、人物状态（HP/火把/金币/护甲/咒语）、背包（10 格、装备与使用、城里可卖）、房间详情（房间内容、怪物与战斗、遗体、门、能做的事、掷骰记录、日志）。
- **城镇画面**：回到镇上会切到独立的一屏：夜景城镇插画 + 商店（买火把、旅馆休息、修理护甲、兑换财宝）+ 背包（可卖）+ 出发进地牢。出发会消耗 1 个火把（有替代光源则免费）。
- **地牢行动**：开锁（1 火把）、破坏房门（0 火把但怪物先手）、用钥匙、安静移动（1 火把、逐怪掷 1d6）、寻找密道（1 火把）、打开宝箱（2d6，双 1 空箱 + 陷阱）、走下楼梯（第 3 层是最终房间）。
- **战斗**：先攻由「开门是否出声」决定；武器骰 + 装备加成一击一怪，怪物回合把伤害汇总后由你选择打 HP 还是某件护甲；14 种怪物词缀（石肤、自爆、无形、不死、复苏、瘫痪、剧毒、死亡之触…）全部生效。
- **资源**：火把（上限 10，进地牢消耗 1，0 火把在地牢里等于死亡，矿工例外）、背包 10 格、5 部位护甲（各自有 HP，掉光即毁）、钥匙、财宝、金币。
- **结局**：击败最终房间的 Boss 即通关（额外 2d6 宝藏）；角色死亡或主动放弃会写进墓地（原书第 24 页那张表）。若地图走到死路（再也没有门也没有楼梯），最后一个房间会自动成为最终房间（这时它也贴着楼梯、两边各一扇门）。
- **3D 骰子**：复用先攻主屏那套 3D 引擎（与 EDH 记血器同一个组件 `components/dnd/DiceRoller`）。引擎是即时结算的，骰子只是把刚才那批结果按顺序回放；回放时会把**引擎算出的点数用 `NdM@点数` 钉在骰面上**，所以看到的骰子和结果显示必然一致。
- **表格速查**：任意时刻都能展开六类地牢的全部表格、核心表（种族/职业/咒语/开门/战利品）与 14 条词缀说明，不必翻规则书。

## 规则数据与扩展

所有表都在 [`resources/content/notequest/`](../resources/content/notequest/)：

| 文件 | 内容 |
| --- | --- |
| `core.json` | 种族、职业、咒语、开门表、战利品、宝箱规则、共用地牢片段/密道/护甲表、14 个词缀、战斗与城镇说明、经济常量、地牢名三段表 |
| `dungeons.json` | 六类地牢（宫殿 / 地穴 / 陵墓 / 庇护所 / 神庙 / 牢狱），每类含陷阱、房间内容、怪物、奖励（财宝·奇物·魔法物品）、Boss、武器 |
| `README.md` | 扩展指南：加地牢类型 / 种族 / 职业 / 咒语 / 词缀 / 物品的方法，以及每个 `kind`、`trigger` 由 `code/lib/notequest/engine.ts` 里哪个钩子实现 |

数据是服务端与前端共用的一份（和 `content/scratch/` 一样），改完 JSON 刷新页面即生效；已有存档保存的是自己的快照，不受影响。

引擎侧只有**新机制**才需要改代码：

- `lib/notequest/engine.ts`：纯函数状态机（`createRun` / `buildHero` / `applyAction`），RNG 可注入；死亡时把遗体与装备落到当前片段（`depositHeroGrave`）；开门时给两边各生成一扇互相重叠的门（`spawnBehindDoor`）；
- `lib/notequest/dice.ts`：`NdM±K` 解析与「2d6 取高」这类特殊掷骰；
- `lib/notequest/map.ts`：格子排版（占地 2×2 起、贴墙摆放且保证与父片段共享墙面、门朝向分配 `assignDoorDirs`、门在墙上的那一格 `doorOpeningCell` / `doorWallCell`、老存档重排）；
- `lib/notequest/data.ts`：规则数据访问层。

界面层在 `code/components/notequest/`：`StartScreen`（存档栏位 / 人物池 / 出发 / 墓地）、`CharacterCreator`（掷骰或自定义建角，也可改已有角色）、`TownView`（城镇与商店）、`MapBoard`（格子地图，含门与拖拽缩放）、`StatusPanel`（人物状态）、`BackpackPanel`（背包）、`RoomPanel`（房间详情、行动与掷骰记录）、`DiceStage`（3D 骰子回放）、`RunManager` / `TableViewer`（存档墓地 / 表格速查）。

## 数据与权限

- 存档写入 SQLite 的 `NoteQuestRun`（一局一条，含完整状态快照 `stateJson` 与摘要列）、`NoteQuestCharacter`（人物池，每个角色一份 `heroJson`）与 `NoteQuestDungeon`（永久地牢，`nodesJson` 是整张地图；`(ownerId, slot, typeId)` 唯一）与 `NoteQuestGrave`（墓地）。四张表都带 `slot`（0/1/2），栏位之间完全隔离。
- 接口（除 `slots` 外都可带 `?slot=`，写操作也可以放在请求体的 `slot` 字段里）：
  - `GET /api/notequest/slots`（三个栏位的概览：进行中的那一局、条数、更新时间）、`DELETE /api/notequest/slots/:slot`（清空该栏位的存档 + 人物 + 地牢图 + 墓地）
  - `GET/POST /api/notequest/runs`、`GET/PATCH/DELETE /api/notequest/runs/:id`
  - `GET/POST /api/notequest/characters`、`GET/PATCH/DELETE /api/notequest/characters/:id`（`PATCH` 支持 `hero` / `status` / `lastOutcome` / `incrementRuns` / `incrementDeaths`）
  - `GET/PUT /api/notequest/dungeons`（`GET ?typeId=xxx&slot=n` 按「栏位 + 类型」取那张永久地图；`PUT` 按 `id` 或 `(账号, 栏位, 类型)` 新建/更新）
  - `GET/DELETE /api/notequest/dungeons/:id`、`GET /api/notequest/graves?slot=n`
  全部要求登录 + `notequest` 权限，写操作要求同源。
- 服务端只做形状与体积检查（快照必须带 `version` / `hero` / `dungeon.nodes`，单条不超过 400 KiB；人物快照 24 KiB；地牢地图 900 KiB），具体字段由前端引擎负责；摘要列由服务端从快照派生，避免客户端传错。存档里的 `characterId` / `dungeonId` 只接受**属于本账号**的 id，别人的 id 会被忽略（存为 null）。
- 每个账户的**每个栏位**最多保留 30 条存档、200 条墓地记录、24 个角色、12 张地牢图；超上限时删除最旧的（有进行中存档的角色/地图会跳过）。栏位与账号都互相看不见。
- 同一条存档变为 `dead` 时只会写一次墓地记录；删除存档不会删除墓地记录（地牢地图里的遗体也不会消失）。

## 本地验证

```powershell
npm.cmd run db:generate
npm.cmd run db:migrate
npm.cmd run smoke:notequest                       # 存档/栏位/墓地接口端到端（含权限与栏位隔离）
npm.cmd run verify:notequest                      # 无头 Chrome 走一遍真实路径并截图
npm.cmd --prefix code install --no-save esbuild
npm.cmd run simulate:notequest -- 60              # 纯 Node 跑 60 局随机探索，校验状态与地图几何
```

引擎是纯函数，所以 `simulate-notequest.mjs` 能在不开浏览器的情况下跑完开门 → 房间 → 战斗 → 掉落 → 往返城镇 → 下楼梯 → Boss → 死亡/通关的完整链路；它同时校验**地图几何**：房间之间不重叠、同一层的每个片段都必须与别的房间墙贴墙（不能飘在空地上）、**一面墙最多一扇门**、相连的两扇门必须互相指向对方、方向相反、共享至少一格墙面。没有装 esbuild 时它会打印提示并跳过。`verify-notequest.mjs` 需要本机有 Chrome / Edge，会走「存档栏位隔离 → 掷骰建角 → 自定义建角 → 切栏位 → 出发 → 城镇 → 地牢 → 点门 → 掷骰记录」，截图写在 `ops/checks/shots/notequest.png`；注意它跑的是 `next build` 的产物，改完前端要先 `npm.cmd run build`。

## 升级与备份

部署更新前运行：

```powershell
npm.cmd run db:generate
npm.cmd run db:migrate
```

`resources/data/box.sqlite` 是唯一需要备份的文件（存档与墓地都在里面）；规则数据在 `resources/content/notequest/`，随代码一起发布。
